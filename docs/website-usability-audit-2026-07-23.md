# 文案生成网站端到端体验审计

## 审计说明

- 日期：2026-07-23
- 范围：文案生成网站，不包含浏览器插件
- 环境：本地未登录演示模式，`http://127.0.0.1:5173/`
- 视口：桌面约 1280 x 720；移动端 390 x 844
- 实际走查：项目创建、重命名、同名项目与删除；对话创建、置顶、切换和未发送草稿；文案库、文件夹、详情、搜索、排序和刷新；参考文案筛选与多选；文案分析、偏好补充、篇幅切换、初稿生成、附件上传、局部改写、读者预演、完成后再编辑、刷新恢复、登录入口和移动端布局
- 严重度：4 = 阻断核心价值；3 = 主要问题；2 = 次要问题；1 = 视觉或文案细节

> 说明：本次体验处于未登录演示模式，因此不能用它判断线上 AI 模型的最终质量。但演示模式本身就是新用户理解产品价值的入口，仍然必须避免“看似成功、实际没有执行”的交互。

## 结论

目前最需要修的不是视觉，而是产品主链路和数据可信度。产品把“选择参考素材”设成了写作起点，却没有在生成前可靠收集“到底要写什么”。系统在缺少主题、读者和真实事实时仍显示“已提交”“已准备好生成”，并把项目名当成主题、自动编造创作信息，最终生成的是写作方法说明，不是一篇可发布文案。第二轮还确认：未登录项目、对话和编辑结果刷新后会直接消失，而首页没有明确警告。

这会造成三层信任损失：用户不知道系统掌握了什么；用户不知道偏好被记到哪里；系统多次提示成功，但结果或数据并不对应。只优化卡片、间距和颜色无法解决这些问题。

建议把核心流程改成：**先说清写作任务 -> 系统提取并让用户确认创作简报 -> 选择或推荐参考素材 -> 展示学到的规律与记忆范围 -> 生成可用初稿 -> 可追踪地修改 -> 可选读者预演 -> 保存与导出。**

## 最高优先级问题

### 1. 未获得写作任务就宣称可以生成

- 严重度：4
- 位置：篇幅设置之后的“文案创作”页
- 观察：用户没有输入主题、目标读者或真实信息。系统却显示“创作信息 / 已提交”，把项目名“产品体验审计 2026-07-23”直接变成内容主题，并自动填入“核心卖点、使用场景、真实细节、推荐理由”。
- 结果：生成内容是“开头不要急着下结论”“正文里保留真实细节”等写作说明，不是文案。
- 为什么不合理：产品在最关键的输入缺失时继续向前，并用确定语气掩盖缺失信息。用户无法得到核心价值，也不知道问题出在自己没填信息还是 AI 能力不足。
- 建议：新对话第一步必须有自由输入的写作任务；系统提取为可编辑简报。主题与至少一条真实事实缺失时，不能显示“已准备好生成”。允许 AI 追问，但不能编造。

### 2. 用户补充了完整需求，但发送后无反馈、无更新

- 严重度：4
- 位置：“文案创作”页底部输入框
- 观察：输入“深圳湾公园新手骑行路线、第一次骑行的人、15 公里、傍晚避晒、周末人多”等信息并发送后，输入框被清空，但创作信息、文案和页面状态完全没有变化，也没有成功或失败反馈。
- 为什么不合理：这是典型的“静默失败”。用户已经做了正确的补救动作，产品却吞掉输入，让人无法判断内容是否被记录。
- 建议：发送后必须出现用户消息、处理中状态和明确结果；创作简报变化要高亮，并允许撤销。失败时保留输入并提供重试。

### 3. 局部 AI 改写没有执行用户指令

- 严重度：4（演示入口）
- 位置：“编辑细调”页
- 观察：圈选段落并要求加入“第一次骑深圳湾、怕晒和路线难、傍晚完成 15 公里”等真实内容，三个候选都没有使用这些信息，只是给原句加句号、停顿或尾巴。
- 额外风险：采用后提示“已采用改写，并记住这次选择”，但这次选择并不代表用户真正偏好，且没有说明记忆作用于当前对话、项目还是整个账号。
- 为什么不合理：主打“学习用户”的产品如果不遵循明确指令，会比普通生成器更快失去信任。
- 建议：候选必须逐项通过“指令覆盖检查”；展示采用了哪些事实和偏好。演示模式做不到时，应明确禁用或提供固定但真正匹配指令的演示，而不是伪装成成功生成。

### 4. 项目、对话、参考素材三层数据语义混乱

- 严重度：3
- 位置：项目列表与对话工作区
- 观察：同一项目在完成旧对话时显示“已选 2 项参考内容”，切换到未选择素材的新对话后又变成“已选 0 项参考内容”。实际旧对话只选择了 1 篇参考、其中包含 2 条标注。
- 观察：新建项目时选择了“护肤口播感”文件夹，进入项目后仍默认展示其他文件夹的素材，必须再次手动筛选。
- 为什么不合理：项目行看似展示项目级数据，实际随当前对话变化；“参考内容”又混淆了参考文章数和标注数。用户无法相信项目状态。
- 建议：明确数据层级。项目列表展示“对话数、最近阶段、最近产出”；对话内展示“已选 1 篇素材、2 条标注”；项目文件夹决定默认素材范围，并允许用户主动扩展。

### 5. 登录入口打开即出现原始系统错误

- 严重度：3
- 位置：登录与注册弹窗
- 观察：没有输入或提交任何内容，打开登录弹窗就出现 `Unexpected end of JSON input`；切换到注册后错误仍保留。
- 为什么不合理：用户会认为账号或网站已损坏，而且这是开发错误文本，不能帮助恢复。
- 建议：修复初始化请求；加载期间显示稳定状态。将技术错误映射为用户能理解的文案，并提供“重试”或“稍后继续使用演示”。登录、注册切换时清理不相关错误。

## 主要问题

### 6. 演示模式和真实能力的边界太晚出现

- 严重度：3
- 观察：未登录也能完整创建项目和生成，直到局部改写结果中才出现“演示模式”字样。用户此前无法知道数据是否保存、AI 是否真实调用、登录后内容是否保留。
- 建议：首页明确显示“本地演示 / 登录后同步”，并说明数据保存范围。任何降级能力都应在操作前说明，而不是在低质量结果后解释。

### 7. 篇幅选择页与当前任务脱节且负担过重

- 严重度：3
- 观察：短、中、长三个选项都展示大段“番茄炒鸡蛋”示例，与骑行和所选素材完全无关；桌面端三个长卡片标题被截断，页面需要读大量无关文本才能选一个字数范围。
- 建议：改为紧凑单选：短 100-200 / 中 300-500 / 长 600-1000 / 自定义。只展示结构差异，不展示无关全文；默认推荐一个并说明原因。篇幅也可以放进创作简报，无需独立成一整步。

### 8. 对话偏好“已记录”，但作用范围和结果不可见

- 严重度：3
- 观察：分析阶段补充“保留互动感、不要投票式结尾、像朋友分享、信息直接”，系统只回复“方向已记录”，原分析不变化，也不说明它影响本次文案、项目还是全局写作画像。
- 建议：提供可见的“本次要求”和“长期偏好”两个层级；默认先记为本次要求，用户主动确认后再进入长期画像。生成结果中可显示“本稿应用了：朋友式分享、直接表达、非投票结尾”。

### 9. 对话名称没有按既定逻辑自动总结

- 严重度：3
- 观察：完整走到生成、编辑、预演和完成后，对话仍叫“新的文案对话”。新建第二个对话后出现两个同名项，只能手动重命名才能区分。
- 建议：获得第一条真实写作任务后自动生成名称；自动命名前用默认名，自动命名后仍允许修改。完成状态不能替代可识别的名称。

### 10. 读者预演的结果看似具体，实际存在对齐错误

- 严重度：3
- 观察：右侧显示“4 条批注”，左侧正文只出现 1、2、3 三个锚点；第 4 条对应文案从“由、使用过程……”中间截断。设置目标用户后，主要变化只是把目标用户字符串替换进通用模板。
- 为什么不合理：批注式界面会让用户误以为反馈精确对应文本，编号和截断错误会放大不可信感。
- 建议：每条批注必须绑定稳定文本范围；无法定位时不要生成锚点。预演应说明依据、置信度和不可判断项。若只是结构检查，名称改为“结构检查”比“读者预演”更诚实。

### 11. 手机端不是响应式重排，而是多个极小的嵌套滚动区

- 严重度：3
- 观察：390 x 844 下，读者预演出现约 110 px、118 px、61 px 高的三个独立滚动区域；正文初始只看得到标题，批注内容几乎被底部按钮挤没。左侧项目与历史对话整块堆到正文上方，占用约三分之一屏幕。
- 建议：移动端将项目/对话导航收进抽屉；正文和反馈改为单一页面滚动或上下 Tab，禁止 61 px 高的内容滚动窗。底部操作固定时必须为内容保留足够空间。

### 12. 完成复制给出成功提示，但本次检查未读到剪贴板内容

- 严重度：3（需要在 Chrome 再确认）
- 观察：点击“确认完成并复制文案”后提示“已复制当前文案”，对话也标记完成，但当前浏览器会话读取到的剪贴板为空。
- 建议：只有 Clipboard API 成功后才显示成功；失败时提供可选中的文本和“再次复制”。增加真实浏览器自动化测试，验证标题、正文和换行完整复制。

## 次要问题

### 13. 参考文案选择缺少任务解释和选择反馈

- 严重度：2
- 观察：用户只看到素材卡片、标签和“开始分析”，不知道应该选风格相似、主题相似还是自己最喜欢的文案。未选择时按钮禁用，但没有解释原因；选择后 CTA 仍不显示将分析多少篇。
- 建议：增加一句明确任务：“选 2-5 篇你希望这次文案借鉴的表达”；CTA 可写成“分析 2 篇文案”，既保留简洁又提供反馈。

### 14. 项目列表不支持判断进度和快速恢复

- 严重度：2
- 观察：项目行主要显示文件夹、参考数量、时间和删除，无法看到对话数、当前阶段、最近一篇文案或是否已完成。
- 建议：项目行优先展示“3 个对话 / 最近：编辑细调 / 2 小时前”，点击后恢复最近打开的对话。文件夹是次级元数据，不应占据主列。

### 15. 新建项目默认值会让用户误创建错误项目

- 严重度：2
- 观察：项目名预填“深圳周末路线项目”，参考文件夹也被静默默认选中。第一次使用的人可能直接提交，误以为这是占位符或推荐。
- 建议：名称使用空值和示例占位；文件夹若是必填要明确标记，若可选则显示“暂不关联”。

### 16. 生成动作被拆成两次“继续”

- 严重度：2
- 观察：篇幅页点击“下一步”后到创作页，仍要再点“生成初版文案”。前一步已经表达了继续意图，却进入一个内容不足、操作重复的中间状态。
- 建议：如果创作简报已确认，下一步直接生成；如果信息不足，进入简报确认而不是显示“已准备好生成”。

### 17. 720p 桌面高度下，创作建议被固定输入框遮挡

- 严重度：2
- 观察：“补充信息 / 校准目标 / 调整语气”建议按钮部分被底部输入框覆盖，用户只看到半截内容。
- 建议：输入框应占正常布局空间，或给滚动容器增加等高底部留白；用 720p 作为最低桌面高度做回归测试。

### 18. 完成后缺少明确的下一步

- 严重度：2
- 观察：完成后仍停留在预演页，只把按钮改为“再次复制文案”。没有“保存为版本、回项目、继续修改、创建新文案”等清晰出口。
- 建议：完成状态提供三个明确动作：复制、返回项目、新建对话。自动保存当前版本并显示保存时间。

### 19. 流程命名和导航不一致

- 严重度：2
- 观察：页面标题叫“文案分析”，流程菜单却叫“学习拆解”。流程菜单允许进入未完成的未来步骤，虽然有空状态恢复，但会让流程看起来全部可用。
- 建议：统一步骤名称；未完成步骤可以展示但应标为“尚未开始”，点击后解释前置条件，而不是像正常可用菜单项。

### 20. 多处交互元素存在嵌套和重名

- 严重度：2
- 观察：项目整行按钮内部又包含重命名和删除按钮；对话按钮内部包含更多操作按钮。多个候选都叫“采用此版”，多个对话菜单都叫“对话更多操作”。
- 风险：点击传播、键盘导航和读屏识别都容易出错，同名对话时尤其无法区分。
- 建议：整行使用链接或非按钮容器，操作按钮独立；无障碍名称带上对象名或候选名，例如“采用更自然版本”“打开‘深圳骑行’的更多操作”。

### 21. 对话管理入口的顺序和可发现性不足

- 严重度：2
- 观察：菜单实际顺序为“置顶、重命名”，与此前确定的“重命名、置顶”不一致；更多操作图标视觉上很弱，同名对话下更难判断操作对象。
- 建议：按高频顺序放“重命名、置顶/取消置顶”；选中或悬停时稳定显示，触屏端始终提供足够点击区域。

## 第二轮补充发现

### 22. 未登录状态下，刷新或重新打开会丢失全部工作

- 严重度：4
- 观察：第一轮创建、完成并编辑过的“产品体验审计”项目，在新标签重新打开网站后消失；项目重命名、置顶、对话、文案和完成状态在刷新后也全部恢复为初始演示数据。
- 为什么不合理：首页允许用户完整走到“完成”，却没有持续显示“临时数据，刷新即丢失”。用户会自然理解为已自动保存。
- 建议：未登录也至少使用本地持久化；更稳妥的是在第一次创建前明确告知保存范围，并提供登录后迁移。页面必须显示“已保存/仅保存在本机/尚未同步”。

### 23. 文案库文件夹数量与真实内容不一致

- 严重度：4
- 观察：“生活方式笔记 2”点进去显示“没有匹配到笔记”；“护肤口播感 3”实际只有 2 条；“全部”只有 3 条，但三个文件夹计数分别为 3、2、2。
- 为什么不合理：素材库是学习用户偏好的数据源。计数和内容不一致时，用户无法判断插件是否同步成功，也无法相信后续分析用了正确素材。
- 建议：所有计数必须来自同一个查询结果；同步过程中显示加载状态，完成后校验总数、文件夹数和列表数。空文件夹不能显示非零数量。

### 24. 素材标题、正文和分类互相矛盾

- 严重度：4
- 观察：标题为“现在 AI 发展这么快，但是还是很多应届生在找互联网的工作”，正文却是“900 人赞过的深圳市区骑行路线”；该内容又被放在“护肤口播感”文件夹。
- 为什么不合理：这不是展示瑕疵，而是会直接污染 AI 学习和写作。系统可能把骑行表达误认为求职主题或护肤风格。
- 建议：导入时校验标题、正文、来源和文件夹；演示数据也必须语义一致。出现异常时标记“待确认”，不得静默进入学习样本。

### 25. 生成结果不遵守篇幅和“必含要点”

- 严重度：4
- 观察：选择“短篇幅，约 0-200 字”，实际正文约 251 字，不含标题；创作简报要求“路线距离”，生成结果只让用户“看好距离”，没有给出任何具体距离。
- 为什么不合理：篇幅和必含信息是可验证的硬约束，不是风格建议。连硬约束都不满足，用户必须人工复核所有要求。
- 建议：生成后执行自动验收：字数、必含事实、禁用表达逐项检查；不通过就自动修正或明确提示缺少真实数据，不能直接展示为可用初稿。

### 26. 筛选后的全选/取消全选范围不透明

- 严重度：3
- 观察：先全选 3 条，再筛选到“语气”，点击“取消全选”只取消当前可见的 1 条；返回“全部”后仍有 2 条隐藏选中，但按钮显示“全选”，页面没有总选中数。
- 为什么不合理：用户很容易把自己不知道的素材带入分析，尤其当素材库扩大后。
- 建议：明确写“全选当前结果/取消当前结果”；始终显示“已选 2 篇”，并提供可展开的已选清单和“一键清空全部”。

### 27. 被选中的未标注素材会被静默忽略

- 严重度：3
- 观察：同时选择一篇有 2 条标注的素材和一篇“未标注”素材后，创作页显示“1 篇参考，2 条标注”，分析完全没有提到未标注素材，也没有解释为什么未使用。
- 建议：选择时说明分析单位。若只学习标注片段，未标注素材应不可选或提示“不会参与”；若整篇也能分析，就要展示它贡献了什么。

### 28. 切换对话会直接丢失未发送内容

- 严重度：3
- 观察：在分析输入框写入一条偏好但未发送，点击“新对话”后没有任何警告；切回原对话，输入内容已消失。
- 建议：按对话保存输入草稿；离开时自动保留。只有真正无法保留时才提示“还有未发送内容”。

### 29. 修改上游设置会静默丢弃下游产物

- 严重度：3
- 观察：生成短篇初稿后返回篇幅设置，改为中篇并继续，原初稿直接消失，页面重新变成“已准备好生成”，没有说明旧稿被替换，也没有版本可恢复。
- 建议：上游变化应提示影响范围，并保留旧版本。允许“以新篇幅生成新版本”，不要覆盖唯一稿件。

### 30. 完成状态不会因继续编辑而失效

- 严重度：3
- 观察：点击“确认完成并复制文案”后对话显示“完成”；随后返回编辑并修改标题，左侧仍保持“完成”。
- 为什么不合理：“完成”应描述当前版本，而不是历史上曾点过一次按钮。
- 建议：完成后继续修改时自动变为“已修改，待确认”；保留“完成版本”和“当前草稿”两个版本及时间。

### 31. 读者预演会对明显无意义的内容给出肯定结论

- 严重度：3
- 观察：把标题改成“完成前标题”后，预演仍评价“标题先把主题和适用人群说清楚”。反馈与文本明显矛盾，说明是在套模板而不是阅读内容。
- 建议：预演先做基本语义校验；无法判断时明确说“标题信息不足”。不要为了填满批注而生成虚假肯定。

### 32. 手机端文案库核心页面不可用

- 严重度：4
- 观察：390 x 844 下，文件夹侧栏固定占约 247 px，只给右侧内容留下约 143 px；搜索、排序、标签和卡片被压扁或截断，页面又没有横向滚动或收起侧栏入口。
- 建议：移动端侧栏必须改为抽屉或顶部选择器；卡片使用单列完整宽度，搜索和筛选独立成可展开工具栏。

### 33. 手机端素材详情接近“无法退出”的长弹窗

- 严重度：3
- 观察：详情弹窗标题被截断，右上关闭按钮在首屏不可见；正文与片段区形成很长的内部滚动，底部动作远离当前视野。
- 建议：移动端详情改成全屏页面或底部抽屉，固定标题栏和关闭按钮，只保留一个主滚动区。

### 34. 附件上传只有文件名，没有可执行闭环

- 严重度：3
- 观察：上传 `.txt` 后只出现文件名；没有上传中/成功状态、内容摘要、移除按钮或用途说明。仅上传附件不能启用发送，已有草稿也不变化。
- 建议：展示文件状态、大小、解析结果和删除入口；附件本身应足以启用“发送并应用”，并明确它将更新简报还是直接参与生成。

### 35. 项目名称允许重复，导致对象无法区分

- 严重度：3
- 观察：可以创建两个“数码产品种草项目”，也可以把另一个项目重命名成同名。两个进入、重命名和删除按钮的名称完全相同，删除确认只显示名称。
- 建议：优先阻止同名，或至少提示并自动添加区分信息；删除确认显示文件夹、最近更新时间和对话数。

### 36. 无效重命名也会篡改“最近更新”

- 严重度：2
- 观察：项目名清空后按 Enter，名称回退为原值，但“最近更新”仍变成当前时间。
- 建议：只有数据真正变化且保存成功后才更新时间；空值应保留编辑状态并显示校验错误。

### 37. 删除完成缺少结果反馈和撤销

- 严重度：2
- 观察：删除空测试项目有二次确认，但确认后项目只是突然消失，没有“已删除”提示或撤销。存在同名项目时也很难确认删的是哪一个。
- 建议：显示“已删除，可撤销”，短期进入回收站；确认框补充足以识别项目的信息。

### 38. 文案库大量禁用控件没有解释

- 严重度：3
- 观察：演示模式下“新建文件夹、删除、重命名、保存、新增片段、编辑片段”全部禁用，但详情弹窗仍提示“选中文字填入片段”，页面没有解释登录后可用还是功能尚未完成。
- 建议：不要展示成看似故障的灰色控件。统一给出“演示模式仅查看，登录后可编辑”的说明和登录入口。

### 39. 刷新按钮没有刷新过程和结果

- 严重度：2
- 观察：点击文案库“刷新”后，没有加载、成功、失败、更新时间或数量变化提示。
- 建议：显示“正在同步”“已同步 3 条，17:20”“同步失败，重试”；插件新增素材时可自动刷新并弱提示变化。

### 40. 所有页面共用根 URL，无法可靠返回、收藏和恢复

- 严重度：3
- 观察：项目页、文案库、六个写作步骤和不同对话的 URL 始终是 `http://127.0.0.1:5173/`。
- 风险：浏览器返回键无法表达“上一步”，刷新无法恢复当前页面，也不能收藏或分享某个项目/对话。
- 建议：为项目、对话和步骤建立稳定路由，例如 `/projects/:id/conversations/:id/edit`；刷新后从持久化状态恢复。

### 41. 流程菜单看起来可点击，实际会无反馈地留在原页

- 严重度：2
- 观察：在清空参考文案后，流程菜单中的“学习拆解”仍是启用状态；点击后页面没有变化，也没有说明缺少前置条件。菜单也不显示当前步骤、已完成步骤和失效步骤。
- 建议：每个步骤显示当前/完成/不可用状态；不可用项解释条件，点击不能静默无效。

### 42. 对话历史缺少长期管理能力

- 严重度：2
- 观察：对话只有重命名和置顶，没有搜索、删除/归档、时间、当前阶段和草稿提示。对话增多后只能纵向滚动并靠名称猜测。
- 建议：至少提供搜索、归档或删除、更新时间和阶段；默认只显示最近对话，历史内容可展开。

### 43. 缺少重新生成、版本比较和有效撤回

- 严重度：3
- 观察：初稿生成后没有“重新生成另一版”；整稿修改输入不会生效，“撤回/恢复”始终禁用。改篇幅会覆盖唯一稿件，局部采用后也没有清晰撤销入口。
- 建议：每次生成或采用都产生版本；支持重新生成、并排比较、恢复上一版，并显示当前版本来源。

### 44. 参考选择页在真实规模下无法使用

- 严重度：3
- 观察：该页只有标签和文件夹筛选，没有搜索、排序、最近使用、收藏或 AI 推荐。当前只有 3 条素材已经需要来回筛选，扩大到几十或几百条后无法高效定位。
- 建议：增加搜索、排序、最近使用和“根据本次任务推荐”；默认只展示最相关素材，不让用户手工遍历素材库。

### 45. “学习用户”的核心价值没有在分析页被证明

- 严重度：4
- 观察：分析只给出通用的开头/中段/收尾和两个重点句，没有展示多篇素材的共性、差异、冲突、用户为什么喜欢、哪些规律是本次临时借鉴、哪些进入长期画像。
- 为什么不合理：这是产品最重要的差异化能力，但用户目前看到的仍像普通文案拆解器。
- 建议：分析结果围绕四件事组织：素材共性；偏好原因；可迁移写法；本次禁用或冲突点。每条结论可追溯到来源，并允许用户确认“记住/仅本次/不准确”。

### 46. “笔记详情”不包含足够的来源信息

- 严重度：2
- 观察：分析页点击“查看详情”只看到短正文，没有作者、文件夹、来源链接、保存时间和用户记录理由；文案库详情又只保存 59 字示例，难以判断是否为完整原文。
- 建议：统一详情模型，至少展示来源、作者、完整正文、标注理由和打开原文；明确内容是否被截断。

### 47. 一次性写作也必须先创建项目，进入成本偏高

- 严重度：2
- 观察：用户不能从首页直接“写一篇文案”，必须先理解项目、参考文件夹和对话三层结构。
- 建议：首页同时提供“快速写一篇”和“新建长期项目”；快速写作完成后再询问是否保存到项目。

## 做得合理的部分

- 项目搜索有明确空状态和恢复文案。
- 同一页面会话内切换对话后，已编辑标题、所处步骤、改写记录和读者建议能够恢复；但刷新后不会保留。
- 直接编辑正文和“圈选 -> 确认范围 -> 输入改写要求”的基本交互链路是成立的。
- 读者预演明确提示“这是推演，不代表真实用户调研或效果预测”，方向是正确的。
- “带着建议回到编辑细调”确实把建议带回了右侧工作区。
- 完成后对话会显示“完成”状态。

## 建议的修复顺序

### P0：先让核心闭环真实可用

1. 先建立可靠持久化和自动保存，禁止刷新丢项目、对话和文案。
2. 修正文案库同步、文件夹计数以及标题/正文/分类数据污染。
3. 重做新对话的写作任务输入与创作简报确认。
4. 禁止在缺少主题和事实时生成；对篇幅和必含事实做自动验收。
5. 修复创作信息发送静默失败、局部改写不遵循指令、复制假成功。
6. 修正项目/对话/素材/标注的数据层级、计数和上下游失效规则。
7. 修复登录初始化原始错误。

### P1：重构流程与信任机制

1. 明确本次要求、项目偏好和长期写作画像三个范围。
2. 自动总结对话名，并展示本稿实际应用了哪些偏好和素材规律。
3. 将篇幅并入创作简报，减少独立步骤和重复点击。
4. 把项目列表改成“恢复工作”的入口，而不是静态文件夹表格。
5. 将“读者预演”改成可验证、可定位的结构反馈，或降低名称承诺。
6. 增加版本历史、重新生成、比较、撤回以及完成后再编辑的状态管理。
7. 为项目、对话和步骤建立稳定路由。

### P2：移动端与视觉收敛

1. 移动端使用抽屉承载项目和对话导航。
2. 文案库移动端改为单列，素材详情改为全屏页面。
3. 消除多层嵌套滚动，保证正文是页面主体。
4. 修复固定输入框遮挡、卡片标题截断和无关长示例。
5. 清理嵌套按钮、重复名称和键盘/读屏问题。

## 下一轮验收标准

- 一个完全不了解产品的人能在 60 秒内说清“我要写什么、给谁看、必须包含什么”，并生成一篇内容而不是方法说明。
- 用户补充的信息在发送后可见、可编辑、可撤销，并确实进入生成结果。
- 刷新、重新打开和切换页面后，项目、对话、未发送草稿和当前版本仍然存在。
- 任意项目、对话、参考文案和标注数量在不同页面显示一致。
- 任意素材的标题、正文、来源和文件夹语义一致；异常素材不会进入学习。
- 篇幅、必含事实和禁用表达均有机器可验证结果，不满足时不会标为可用初稿。
- AI 每次说“已记录”时，都能说明记录范围并让用户查看或删除。
- 所有成功提示都由真实成功状态触发；网络或权限失败不会丢失输入。
- 已完成文案再次修改后自动回到“待确认”，并能恢复上一完成版本。
- 390 x 844 下只保留一个主要纵向滚动区域，用户能完整使用项目页、文案库、编辑和预演。
- 登录弹窗初始无错误，失败信息为中文且包含下一步。

## 未覆盖风险

- 未使用真实账号验证云端同步、跨设备恢复、计费和线上 AI 质量。
- 只删除了本轮创建的空测试项目；包含真实对话和版本的删除、回收站与恢复仍需单独测试。
- 剪贴板问题需要在常规 Chrome 与正式部署环境复测，以排除内嵌浏览器权限差异。
