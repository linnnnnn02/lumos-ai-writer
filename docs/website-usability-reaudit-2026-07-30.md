# Lumos 网站用户体验复查

## 复查说明

- 日期：2026-07-30
- 环境：本地未登录演示模式，`http://127.0.0.1:5173/`
- 主要视口：桌面约 1280 x 720
- 方法：分别以第一次使用者和已有项目的回访用户身份，实际走查项目列表、新建项目、需求输入、对话切换、参考选择、编辑、历史版本、读者预演、文案库及账号入口。
- 严重度：4 = 阻断核心价值；3 = 主要问题；2 = 次要摩擦；1 = 视觉细节。
- 本文是对 `website-usability-audit-2026-07-23.md` 的复查，不替代原审计。

## 一句话感受

主流程已经从“我不知道下一步做什么”改善为“我大致知道怎么完成一篇文案”。当前最大的阻力不再是页面布局，而是系统状态经常互相矛盾：数量、阶段、已选素材和批注编号对不上。用户会因此怀疑素材有没有保存、AI 到底参考了什么、当前稿是否真的处于页面所说的阶段。

## 本轮实施状态

2026-07-30 已完成第一批状态一致性修复：文案库数量改为从实际笔记列表计算；演示素材的标题、正文和文件夹语义已对齐；参考选择按素材篇数计数并持续展示已选标题；项目会恢复到真实的读者预演页面；重叠批注在左右两侧统一过滤并连续编号；对话菜单顺序改为“重命名、置顶/取消置顶”，且支持 `Esc` 关闭后返回触发按钮。

同日已完成第二批减疑与降噪修复：载入旧数据时，仅对仍使用系统默认名称的对话按首次写作需求补全标题；新建项目默认“暂不关联”素材文件夹，并明确关联只影响 AI 的优先推荐；文案库将演示状态标为“只读”，持续解释权限并提供就近登录；参考页的标签只保留在顶部，筛选弹层只负责文件夹；项目删除不再占据独立操作列，仅在行悬停或键盘聚焦时出现，并保留说明与二次确认。

第三批已补齐编辑页的真实保存状态，并收敛读者预演操作：预演反馈出现后，顶部不再重复“确认成稿”，唯一确认动作留在反馈底部；普通“返回编辑”和“将建议带回编辑”采用不同文案。项目打开与对话切换只更新最近打开时间，不再改写内容更新时间；项目列表按真实更新时间倒序并明确展示排序规则。

第四批完成桌面与 390 x 844 移动端回归：编辑页在窄屏改为正文、AI 助手纵向顺序阅读，不再强行各占半屏；顶部次要操作压缩为带说明的图标，主确认按钮保留文字；编辑与预演使用独立页面生命周期，跨流程跳转不会继承上一页滚动位置。宽屏正文保持受控阅读宽度，AI 助手仅在超宽视口并排出现。

第五批补齐项目、对话与可见阶段深链接：需求、参考、编辑和预演均可刷新、收藏并通过浏览器前进/后退恢复；失效对话会回退到有效对话，失效项目会回到项目页；新标签页打开分享链接后，“返回项目”不会把用户带离产品。

2026-07-31 完成第六批本地数据一致性修复：插件保存笔记时会在同一个存储事务中重算文件夹数量，侧栏数量直接从实际笔记列表派生；保存期间也不再漏掉文件夹数量刷新。网页在窗口聚焦或标签页重新可见时会合并触发后台刷新，刷新期间保留已有文案库，不再闪为空白；失败时保留上次数据并提示重试。插件预览实测移动一篇笔记后数量由 `3/1/1` 即时变为 `2/2/1`。

2026-07-31 完成真实账号的线上基线验收：生产站账号可自动恢复登录，云端状态最终稳定为“已同步”，文案库成功加载 `1` 个文件夹和 `4` 篇真实笔记，文件夹数量与列表一致。新版发布后，生产站项目深链接已通过冷启动、新标签页和重新进入项目回归，能够恢复正确的项目、对话与“准备初稿”阶段。

2026-07-31 修复云端同步失败提示不可关闭的问题：悬浮提示增加“立即重试”和关闭入口，连续失败按同一次故障处理，用户关闭后不会被后台重试反复打断；页头保留低干扰的失败状态。保存失败会按 `5 / 10 / 20 / 30` 秒递增间隔自动重试，恢复连接后自动回到“已同步”。真实账号下暂停本地 API 验证通过：关闭提示后首轮自动重试失败未重新弹出，API 恢复后未操作即自动同步成功。

2026-07-31 完成空状态与阶段恢复收尾：编辑页无初稿时只显示“需求与参考”和“生成初稿”，不再展示历史版本、预演和完成等无效操作；空状态在移动端上移并收紧。阶段恢复改为依据真实产物判断，无需求回需求页、未分析回选择参考、已分析但无初稿回准备初稿，只有存在初稿时才恢复编辑、预演或完成。真实云端旧项目从错误的 `stage=review` 自动纠正为 `stage=draft`，项目列表、刷新和重新进入均显示“准备初稿”。生成页统一使用“初稿”术语，并隐藏无初稿时不可用的“返回编辑”。

2026-07-31 新版发布后的真实账号验收发现，项目页账号角标能显示 `1` 个文件夹、`4` 篇文案，但首次进入文案库可能因初始化阶段的重复并发读取而短暂显示 `0`，并报 `Unexpected API error`；手动刷新后恢复。已在本地修复请求风暴：账号角标直接复用文案库状态，不再额外发起四路读取；页面激活刷新不会与正在进行的首次加载重叠；只读 GET 遇到一次瞬时 `5xx` 会受控重试；只要存在成功缓存，后续同步失败也不会清空素材。真实账号下已通过首次进入文案库、`#library` 冷刷新和项目深链接新标签页恢复，均稳定显示 `1` 个文件夹、`4` 篇文案和正确的“准备初稿”阶段。

2026-07-31 完成真实插件连续采集的端到端验收：生产插件在同一测试文件夹连续保存 `4` 篇真实小红书笔记，每次保存后插件文件夹数量立即增加，保存按钮不再等待网络；成功反馈收敛为按钮内“已保存”和单独一行“云端已同步”。插件使用持久化后台队列上传，一次标注最多合并为一次幂等请求，失败任务可重试且不会丢失本地数据。生产网页重新获得焦点后自动从 `1` 个文件夹、`4` 篇文案刷新为 `2` 个文件夹、`8` 篇文案，新增文件夹及四篇标题全部一致，确认“连续采集 -> 后台上传 -> 网页聚焦刷新”链路通过。测试云端文件夹随后已移入回收站。

本次验收同时确认一个仍待处理的边界：插件本地库与网页云端库目前不是双向同步。网页删除或移动云端内容不会自动清理插件的 `chrome.storage.local` 副本；跨端删除、恢复和冲突处理仍需单独设计，不能因为上传链路通过就标记为完成。

## 用户旅程感受

### 1. 项目列表

第一眼能理解这里是恢复工作的入口。搜索、新建项目和文案库位置清楚，项目名称、对话数、阶段、文件夹和时间也容易扫读。

但“删除”作为低频破坏性操作长期占据每一行最右侧，视觉权重仍然偏高。项目时间会因打开或查看流程而更新，因此“最近更新”更像“最近访问”，含义不够准确；项目顺序又没有随该时间变化，用户无法判断排序规则。

### 2. 新建项目

项目名称输入很直接，但“参考文件夹”缺少用途说明，并且必须从已有文件夹中选择。没有“暂不关联”选项，默认又是“护肤口播感”。第一次写骑行、求职或新领域内容的用户，会担心系统错误学习了不相关素材。

### 3. 描述需求

这是本轮最顺畅的页面。标题、说明、较大的输入框、示例和“至少 4 个字”规则都能帮助用户开始。修改需求时也能看到“返回参考”，取消修改不会把用户送回项目页。

但顶部项目名距离主要内容较远，项目与参考文件夹只在输入框底部弱展示。对熟练用户影响不大，新用户仍不容易理解“项目、对话、参考文件夹”三层关系。

### 4. 对话列表

侧栏默认隐藏是合理的，避免历史对话挤压当前任务。当前问题是三个对话都叫“新的文案对话”，用户必须逐个点开才知道是需求、编辑还是已完成状态。切换后侧栏自动关闭，页面可能从需求输入直接跳到完成稿，状态变化很突然。

三点菜单当前顺序仍是“置顶、重命名”，与既定的高频顺序“重命名、置顶”不一致。侧栏顶部与页面左上角还同时出现返回项目入口和关闭入口，图标虽然都有悬停提示，但首次使用仍需要短暂判断。

### 5. 选择参考

“暂无高匹配建议时可以直接生成”方向正确，没有强迫用户为了完成流程而选择无关素材。“修改需求”与“返回编辑”也形成了可理解的回路。

真正的问题是选择状态不可信。在一个对话中，页面显示“已找到 1 篇较相关素材”，可见素材标记为未选，主按钮却写“用 2 条参考生成”。在另一个对话中，手动选择 1 篇素材后进入“修改需求”，再点“返回参考”，页面折叠回空推荐状态，所选素材完全不可见，只剩“用 1 条参考生成”。用户知道有东西被选中，却不知道是哪一篇，也没有清空或查看已选的入口。

“全部 / 开头 / 整体 / 语气”与“筛选”弹层中的标签重复，两个入口表达的是同一维度。素材规模增大后，用户会在“用顶部 Tab 还是点筛选”之间犹豫。

### 6. 编辑文案

直接点击文字编辑、圈选后用 AI 修改、历史版本、需求与参考、读者预演和完成复制，核心工具都能被找到。历史版本说明“恢复会新建一版，不覆盖现有记录”，给人的安全感较好。

编辑页没有持续可见的“正在保存 / 已保存在本机 / 已同步”反馈。用户修改完标题或正文后，只能回项目页确认时间变化，无法在当前工作区确认保存结果。完成稿再次打开时按钮变成“再次复制”，逻辑可以理解，但完成后仍可直接编辑，应该同时明确显示“当前稿是否仍与已完成版本一致”。

### 7. 读者预演

左右对照和“这不是用户调研或效果预测”的提示是正确方向，反馈也能带回编辑区。问题是精确批注的承诺仍然高于实际可靠性：右侧有 4 条批注，左侧只出现 1、2、4 三个可见编号，第 3 条和第 2 条指向同一段却没有独立锚点。

顶部已有“返回编辑 / 再次复制”，右侧底部又出现“带着建议返回编辑 / 再次复制文案”。长内容中保留底部操作有价值，但上下两组动作的语义不完全一致，需要明确一组是全局动作、一组是处理建议后的动作，否则像重复按钮。

### 8. 文案库

文件夹导航、搜索、排序、标签和卡片结构比旧版清楚。实际使用时仍出现最严重的数据一致性问题：侧栏显示“护肤口播感 3 / 生活方式笔记 2 / 数码科技 2”，实际列表分别只有 2、0、1 篇；“全部”只有 3 篇。用户会直接怀疑插件保存失败或素材丢失。

素材语义也存在冲突。例如标题是“现在 AI 发展这么快，但是还是很多应届生在找互联网的工作”，正文却在讲深圳骑行，并被放进“护肤口播感”。这会让用户进一步怀疑 AI 学到的是错误内容。

演示模式下，新建文件夹、重命名、删除、新增片段和保存全部禁用，但页面只显示很弱的“Demo”，没有“登录后可编辑”的解释或就近登录入口。界面因此像功能损坏，而不是有意限制。

### 9. 登录与账号恢复

登录、注册窗口现在尺寸一致，切换稳定；忘记密码入口清楚，找回页明确说明“发送链接，不会立即修改密码”，并提供返回登录。这个区域本轮没有发现新的结构性问题。

本地环境显示“登录服务暂时未连接”，属于环境状态，本轮不据此判断线上登录质量。

## 优先问题清单

### P0：先恢复状态可信度

1. **[已完成] 文件夹数量与实际列表不一致，严重度 4。** 插件与网页均由实际笔记列表计算数量；插件保存事务同步重算持久化数量，网页重新激活时后台刷新云端数据。
2. **[已完成] 参考选择状态互相矛盾，严重度 3。** 已选素材按笔记聚合持续显示在结果上方，可逐篇移除或清空；切换推荐、全部素材、标签和文件夹时不会隐藏选择状态。
3. **[已完成] 读者预演编号无法一一对应，严重度 3。** 无法定位和重叠的文本范围会在渲染前过滤，可见批注按最终范围重新连续编号，正文锚点与右侧批注保持一一对应。
4. **[已完成] 素材标题、正文和文件夹语义冲突，严重度 4。** 新增“参与学习 / 待确认 / 不参与学习”三态；只对正文过短或明确领域冲突的高置信素材自动拦截。待确认和手动排除的素材仍保留在文案库，但不会进入需求推荐、参考分析、初稿输入和长期写作画像。用户可在笔记详情中确认内容无误或明确设为不参与学习。
5. **[已完成] 项目阶段与用户当前页面可能不一致，严重度 3。** 恢复阶段现在由需求、分析和初稿的真实可用性决定；项目列表、深链接和重新进入项目使用同一判定结果。
6. **[已完成] 准备初稿页的“当前理解”与参考数量互相矛盾，严重度 3。** 页面摘要改为依据当前已选文案和标注实时组装，不再将历史分析文案与当前选择状态混合展示，也不会为修复界面文案额外调用 AI。
7. **[已完成] 登录用户刷新时会先闪出本机演示项目或“0 篇参考”，严重度 3。** 首次云端项目和文案库都恢复完成前，只展示轻量的“正在恢复工作区”状态，不再短暂暴露与当前账号无关的演示文案或错误参考数；后台重试仍保留已有内容，不会将整页替换为加载态。

### P1：减少犹豫和误操作

1. **[已完成] 对话名称不可识别，严重度 3。** 首次提交需求后生成简短标题；载入旧数据时修复仍使用系统默认名称的对话，不覆盖用户自定义标题。
2. **[已完成] 新建项目强制绑定默认文件夹，严重度 3。** 默认“暂不关联”，并解释关联只影响 AI 优先推荐，之后仍可浏览全部素材。
3. **[已完成] 演示模式禁用控件无解释，严重度 3。** 文案库顶部持续显示“演示只读”、权限说明和就近登录入口。
4. **[已完成] 参考筛选入口重复，严重度 2。** 标签只保留在顶部主栏；筛选弹层收敛为文件夹范围，按钮直接反馈当前文件夹。
5. **[已完成] 编辑页缺少保存反馈，严重度 2。** 编辑标题下持续复用真实的本机保存/云端同步状态，失败时显示自动重试提示。
6. **[已完成] 项目删除长期可见，严重度 2。** 删除改为行尾悬停/聚焦操作，不占独立列，保留悬停说明和二次确认。
7. **[已完成] 对话菜单顺序与约定不一致，严重度 2。** 已调整为“重命名、置顶/取消置顶”。

### P2：收敛信息层级

1. **[已完成]** 区分“最近访问”和“最近内容更新”，项目列表按真实内容更新时间倒序并明确排序规则。
2. **[已完成]** 读者预演只保留一个确认成稿入口；普通返回与携带建议返回使用不同命名。
3. **[已完成]** 编辑页正文保持受控阅读宽度；AI 助手仅在超宽视口并排，窄屏改为纵向顺序阅读。
4. **[已完成]** URL 编码项目、对话与当前可见阶段；刷新、收藏、前进/后退均可恢复原位置，过期链接会回退到有效对话或项目页。

## 已经改善并应保留

- 项目搜索、无结果提示和返回项目路径清楚。
- 浏览器返回可以从项目工作区回到项目列表。
- 需求输入页只有一个主要任务，说明、示例和快捷键都服务于输入。
- 修改需求后可以返回原参考步骤，已输入需求不会丢失。
- 无高匹配素材时允许直接生成，不强迫用户选择无关素材。
- 历史版本可查看且恢复不会覆盖当前记录。
- 读者预演明确降低了“模拟反馈”的真实性承诺。
- 图标按钮具备可读的无障碍名称，近期补充的悬停提示方向正确。
- 登录、注册与找回密码的尺寸、入口和返回路径已趋于稳定。

## 建议实施顺序
