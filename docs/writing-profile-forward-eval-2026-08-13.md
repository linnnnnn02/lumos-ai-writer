# 表达档案真实前向评测

日期：2026-08-13

## 目标

验证用户写作模型是否能把素材共性与跨项目修改聚合为稳定规则，并在不泄漏候选偏好、不补写事实的前提下影响后续初稿。

固定输入使用两篇不同素材、两次跨项目反馈和一条明确长期纠正。A/B 初稿共用同一份相机使用简报与事实；A 不带表达档案，B 额外带学习后的账号档案。

## 首轮发现

- `user-writing-model@1.4.3` 正确学到“不在结尾突然上价值”，但把“时间节点”“实际使用顺序”“可观察动作”拆成三条候选。
- 结果只有结尾规则进入 B 组，关键 progression 机制没有生效。
- A 组确定性评分 14，B 组 13，不能证明个性化稿更好。
- B 组补写了输入未提供的“也不着急”，事实审计没有识别。
- 中等篇幅首次生成还暴露了 197 字距离 201 字下限很近、两次修复仍失败的稳定性问题。

## 修复

- 写作模型升级到 `1.4.4`：按未来写作动作聚类，不按素材标签拆分；明确把时间节点、使用顺序和具体动作合并为同一 progression 规则。
- 初稿 Skill 升级到 `1.10.1`：明确第一人称心态也是事实，写作画像只能改变已知事实的表达方式，不能创造用户感受。
- 增加本地确定性兜底，拦截 brief 未支持的典型主观补写，并送入既有自动修复流程。
- 增加可重复付费 benchmark，默认拒绝运行，只有带 `--confirm-paid` 才调用模型；每阶段落盘，失败时保留画像、基线、用量和错误。
- 报告把“链路生效”“安全通过”“观察到质量增益”分开，不再把偏好 ID 已应用等同于文案变好。

## 复测结果

- `user-writing-model@1.4.4` 将素材与反馈合并为一条已验证 progression 规则，并保留明确的“不拔高结尾”规则。
- 两条 active 规则都正确进入 B 组；反常识开头仍为 candidate，没有泄漏。
- A/B 必含事实、表达边界与事实审计均通过，说明偏好上下文没有破坏事实覆盖。
- A 组评分 16，B 组 15。由于固定简报本身已经包含“第一次、第三次、现在”，基线自然命中时间推进，本组仍未观察到明确质量增益。
- 第三次验证触发自动修复后，DeepSeek 审计返回非 JSON；系统拒绝结果而非伪装成功。该失败提示后续需要单独提高审计响应稳定性。

## 结论

当前可以确认：偏好学习、自动验证、场景过滤和下游应用链路已经打通，候选规则不会影响初稿。仍不能确认：仅靠这组样本，表达档案已经显著提升文案质量。

下一轮应使用不被简报直接提示的语言层偏好做盲测，例如句式节奏、固定替换或禁用表达，并增加重复运行，而不是继续用时间顺序这种会被任务事实直接暴露的指标。

本轮可见用量估算下限为 CNY 0.058；首次旧脚本中断前的部分成功调用没有落盘，实际总额预计低于 CNY 0.1。
